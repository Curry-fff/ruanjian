## 1. 程序能做什么

一个命令行程序，按作业要求生成小学四则运算题目并给出答案，也能批改题目文件 + 答案文件：

```bash
python Myapp.py -n 10 -r 10                        # 生成 10 道 10 以内的题目
python Myapp.py -n 10000 -r 100                    # 生成一万道题目
python Myapp.py -e Exercises.txt -a Answers.txt    # 批改并写出 Grade.txt
```

### 与作业需求的对照

| 作业要求 | 实现情况 | 说明 |
| --- | --- | --- |
| `-n` 控制题目个数 | ✅ | `-n 10` 生成 10 道题 |
| `-r` 控制数值范围，且必须给定 | ✅ | 缺少 `-r` 时报错并以退出码 2 打印完整帮助 |
| 计算过程不产生负数（`e1 − e2` 中 `e1 ≥ e2`） | ✅ | 构造减法时按数值大小摆放左右孩子 |
| `e1 ÷ e2` 的结果是真分数 | ✅ | 构造除法时要求 `0 < e1 < e2`，每个除法子表达式都成立 |
| 每道题运算符不超过 3 个 | ✅ | `--max-ops` 可再收紧到 1~3 |
| 同一次运行内题目不重复 | ✅ | 规范键查重，覆盖 `+`/`×` 的交换律等价 |
| 题目写入当前目录 `Exercises.txt` | ✅ | `--out-dir` 可改目录，默认就是当前目录 |
| 答案写入当前目录 `Answers.txt` | ✅ | 真分数写成 `3/5`、`2'3/8` 的形式 |
| 支持一万道题目 | ✅ | 一万道题 0.17 秒、峰值内存 6.1 MB，见 `bench/report.md` |
| `-e <exercisefile> -a <answerfile>` 统计对错 | ✅ | 结果写入 `Grade.txt`，格式为 `Correct: 5 (1, 3, 5, 7, 9)` |

附加能力（超出作业要求）：`--strict-range`（中间结果也不超过范围）、`--ascii`（输出 `+ - * /`）、
`--seed`（复现同一批题目）、判分时容忍题号前缀 / 全角符号 / GBK 编码 / 未约分答案。
图形界面未实现——命令行已覆盖全部功能需求。

## 4. 命令行参数

| 参数 | 说明 |
| --- | --- |
| `-n N` | 生成题目的个数，`N ≥ 1` |
| `-r R` | 题目中数值（自然数、真分数、真分数分母）的范围 `[1, R)`；生成模式下**必须给定** |
| `-e FILE` | 待批改的题目文件（与 `-a` 配对使用） |
| `-a FILE` | 待批改的答案文件（与 `-e` 配对使用） |
| `--max-ops K` | 每道题最多几个运算符，默认 3，允许 1~3 |
| `--strict-range` | 更严的范围约束：每一步中间结果也必须小于 `R` |
| `--ascii` | 用 `+ - * /` 输出运算符（默认是作业说明里的 `+ − × ÷`） |
| `--seed S` | 随机种子，用于复现同一批题目 |
| `--out-dir DIR` | 输出目录，默认当前目录 |
| `-h, --help` | 打印帮助 |

退出码：`0` 成功；`1` 运行期错误（文件读不到、答案行数对不上等）；`2` 参数错误（会同时打印帮助）。

## 5. 输出文件格式

| 文件 | 内容 | 例子 |
| --- | --- | --- |
| `Exercises.txt` | 每行一道题，行尾是 ` = ` | `1/6 + 1/8 = ` |
| `Answers.txt` | 每行一道题的答案 | `7/24`、`2'3/8`、`3` |
| `Grade.txt` | 两行统计 | `Correct: 5 (1, 3, 5, 7, 9)` |

* 运算符与等号前后都有空格（作业说明的“分隔符”要求）；等号后保留一个空格。
* 分数一律写成最简形式：真分数 `3/5`，假分数写成带分数 `2'3/8`。

## 6. 几个关键设计决定（免得看到题目后觉得奇怪）

1. **`-r` 限制的是题目里出现的数，不是答案。** 作业原文是“控制题目中数值（自然数、真分数和真分数分母）的
   范围”，因此 `-r 10` 只保证**每个操作数**小于 10，中间结果与最终答案仍可能大于 10（例如 `9 × 9 = 81`）。
   如果老师要求“答案也在范围内”，用 `--strict-range` 即可切换成更严的语义。
2. **除法的结果按“真分数”严格实现**：`e1 ÷ e2` 必须满足 `0 < e1 < e2`，所以不会出现 `6 ÷ 3 = 2`。
   这是作业“其结果应是真分数”一句最直接的读法；`9 ÷ 3` 之类的整除题因此不会出现在结果里。
3. **`-r 1`、`-r 2` 这种极小范围**：可用的数太少，去重后能造的题目有限（例如 `-r 1` 时范围内只有 0）。
   程序会尽力生成、及时收手，并在 stderr 提示“最多只能造出 N 道，请把 -r 调大”，**不会**无限重试。
4. **不出现 `0 + x`、`x × 0`、`0 − 0` 这类白给的形状**：0 仍是合法的自然数，只在这些退化位置上被避开，
   以 `-r 4` 及以上为准。
5. **去重规则与作业说明一致**：只允许“交换 `+`/`×` 的左右孩子”这一种等价变形，
   所以 `23 + 45` 与 `45 + 23` 重复、`3 + (2 + 1)` 与 `1 + 2 + 3` 重复，
   而 `1 + 2 + 3` 与 `3 + 2 + 1` **不算**重复（后者要把 `3 + 2` 当整体，靠交换做不到）。


* 测试：78 个用例，覆盖格式解析、括号打印、作业里点名的去重例子、生成约束、判分格式、
  命令行退出码与一万道题的规模测试。逐条说明见 `docs/测试用例.md`。

## 9. 常见问题

| 现象 | 原因与处理 |
| --- | --- |
| 报错“缺少 -r 参数” | 生成模式必须给 `-r`，例如 `-r 10` |
| 提示“最多只能造出 N 道题” | `-r` 太小、题目空间被穷尽，把 `-r` 调大即可 |
| 批改报错“答案文件只有 X 行” | 答案文件与题目文件行数不一致，需要一一对应 |
| 批改报错“找不到文件” | 路径写错，或没在文件所在目录执行 |
| 题目里出现了 `= ` 结尾的空格 | 这是作业说明里“等号前后加空格”的写法，判分时会自动忽略 |
| 提交记录里的作者名不对 | `git config user.name "你的名字"`、`git config user.email "你的邮箱"` 后重新提交 |
| 推送时报 `fatal: not a git repository` | 你不在仓库目录里。`cmd.exe` 跨盘符必须写 `cd /d "D:\桌面\deepseek\arithmetic-generator"`（只写 `cd "D:\..."` 会静默失败），或直接用 `git -C "D:\桌面\deepseek\arithmetic-generator" push -u origin arithmetic-generator` |
| 推送时报 `Recv failure: Connection was reset` | git 默认不走 Windows 系统代理。先打开加速器，再给 git 配一次代理：`git config --global http.proxy http://127.0.0.1:7890`（端口按你的加速器改） |
