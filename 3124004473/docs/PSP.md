## 二、各阶段实际做了什么

| 阶段 | 实际内容 |
| --- | --- |
| Estimate | 拆出"读题 → 定算法 → 写代码 → 测试 → 性能 → 文档"六个可操作的小任务，逐个估时 |
| Analysis | 逐条解析题目约束（尤其"只能读写指定文件"）；确定用字符 n-gram 而非分词；检索并核对课程下发的真实语料；学习位并行 LCS 算法 |
| Design Spec | 写出 [`design.md`](design.md)：模块划分、调用关系、五路信号定义、异常与退出码约定 |
| Design Review | 复查分层是否清晰、哪些函数需要画流程图（结论：调用关系图足够，算法用公式表达更精确） |
| Coding Standard | 定下：全中文注释、模块级文档字符串、`pylint` + `flake8` 双检、`snake_case` 命名、单行 ≤ 110 字符 |
| Design | 确定 `exceptions / textio / normalize / tokenize / similarity / engine / cli` 七层结构，以及"越靠下越纯"的原则 |
| Coding | 实现全部模块；随后用 176 个测试先行验证，再做性能优化 |
| Code Review | 通读全部代码，把 `%` 格式化统一改成 f-string，清理不可达的防御分支，补全所有函数文档字符串 |
| Test | 从 176 个用例扩到 212 个；用覆盖率报告反查未覆盖行，逐条补测试或删死代码，最终达到 100% |
| Test Report | 整理覆盖率报告、性能基准、权重标定实验的结论 |
| Size Measurement | 统计代码行数、用例数、覆盖率、耗时等量化指标 |
| Postmortem | 复盘估时偏差与踩过的坑（见下） |

## 三、估时偏差分析

### 偏差最大的三项

| 阶段 | 预估 | 实际 | 偏差 | 原因 |
| --- | ---: | ---: | ---: | --- |
| Test | 90 | 180 | **+100%** | 低估了"用覆盖率反查缺失用例"的工作量。补测试的过程中还发现了两个真实缺陷（见下），改完必须重跑全部用例 |
| Coding | 180 | 240 | +33% | 性能优化（位并行 LCS）本不算在编码里，但产生了一大段新算法与配套对拍测试 |
| Analysis | 90 | 120 | +33% | 花在"确认真实语料长什么样"上的时间远超预期——语料只有 `add` 变体，`del`/`dis` 需要自己按题面合成才能做准确度评估 |

### 偏差最小的三项

`Design Review`（20→20）、`Estimate`（30→25）、`Size Measurement`（15→20）
都是"有明确产出物、边界清楚"的任务，估时容易准。经验：**越难界定"做完
没有"的阶段，越容易低估。**

### 测试阶段实际发现的两个真实缺陷

1. **BOM 分支的 `UnicodeDecodeError`**：原实现在检测到 `FF FE` 开头时直接
   按 UTF-16 解码，但一个以 `FF FE` 开头、长度却是奇数的文件并不是合法
   UTF-16，会抛出未捕获的异常——正好踩中"发生异常退出"的扣分项。
   改成"BOM 只是候选编码之一，失败就继续试下一个"后修复，并由
   `test_truncated_utf16_bom_falls_back_instead_of_raising` 钉住。
2. **性能优化引入的静默语义改动**：把逐字符 `lower()` 换成整串 `lower()`
   后，等价性测试失败——`str.lower()` 会应用 Unicode 的希腊词尾 sigma 规则
   （`ΣΟΦΟΣ` → `σοφος`），逐字符版本给出 `σοφοσ`。确认对本项目无影响后，
   如实写进测试而不是把它藏起来。

## 四、如果重做一次

1. **先写测试骨架再写实现**。本次是"实现 → 补测试"，结果测试阶段占了
   全部时间的 19%。若一开始就按故障模式列测试清单，编码时会更快收敛。
2. **尽早拿到真实语料**。算法准确度只能靠真实语料判断，凭感觉调参
   很容易过拟合。这次是靠检索公开仓库找回了课程语料才做成标定实验。
3. **性能分析要用对工具**。第一版用 `cProfile` 得出"`normalize` 占 64%"
   的结论，而直接分阶段计时显示真正的瓶颈是顺序信号（95.6%）——`cProfile`
   对"调用次数极多、单次极廉价"的函数会严重高估。**先用不插桩的方式
   定位阶段，再用 profiler 看函数级细节**，顺序反了会白花时间。
