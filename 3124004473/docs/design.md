### 调用关系

```
main.py
  └── cli.main(argv)
        ├── argparse                      解析三个位置参数
        ├── PlagiarismChecker.compare_files
        │     ├── textio.read_text_file   读入两篇论文（×2）
        │     ├── normalize.normalize     抹平书写差异（×2）
        │     ├── tokenize.ngram_frequencies   生成 1/2/3-gram 指纹（×6）
        │     ├── similarity.*            计算五路信号
        │     └── SimilarityWeights       加权融合
        └── textio.write_answer_file      写出两位小数
```

**分层原则**：越靠下的模块越"纯"。`similarity` 是纯函数（输入词频字典、
输出浮点数，不碰文件、不看时间），因此可以穷举边界做单元测试；
`textio` 是唯一接触磁盘的模块，所有 IO 异常都在这一层被翻译成项目异常；
`cli` 只做参数解析、调用与退出码映射，不含任何算法。

这样划分的好处是：算法改动不会波及 IO，IO 改动不会波及算法，测试可以
只针对出问题的那一层写。

## 三、算法设计

### 3.1 为什么用字符 n-gram 而不是分词

中文查重最常见做法是 jieba 分词 + TF-IDF 余弦。本项目刻意**不用分词**：

1. **零依赖**。jieba 是第三方库，而评测环境不一定能联网安装。少一个依赖
   就少一处"在我机器上能跑"的失败点。本项目全部只用标准库。
2. **对"改"更稳**。分词结果依赖词典，把"星期天"改写成"周天"会让分词
   结果完全不同；字符 n-gram 只关心相邻字符，改写一个字只破坏 n 个窗口。
3. **对增删改都线性响应**。删除一段只让局部窗口失配，插入一段只新增
   局部窗口，不会像分词那样出现"边界错位导致整句错位"的连锁反应。

代价是丢失词边界信息，因此引擎同时使用多种 n 值互补（见 3.3）。

### 3.2 归一化：先抹平无意义的差异

在切分之前，先把"书写层面的噪音"消掉，否则它会被误当成抄袭证据：

1. **NFKC 兼容分解**：全角 `ＡＢＣ` → `ABC`、全角逗号 `，` → `,`；
2. **丢弃空白与标点**（默认）：只保留 `str.isalnum()` 为真的字符。
   这一步让"把逗号改成句号""随手加换行"完全不扣分；
3. **大小写折叠**：`Python` 与 `python` 视为同一内容。

### 3.3 五路信号与融合

单一度量都有明显盲区，因此引擎计算五路信号再按权重融合：

| 信号 | 数学定义 | 回答的问题 | 权重 |
| --- | --- | --- | --- |
| `sequence_ratio` | `2·LCS / (len_a + len_b)` | 两篇文本的**顺序**有多接近？（唯一顺序敏感的信号） | 0.30 |
| `unigram_coverage` | `Σ min(tf_a, tf_b) / Σ tf_b`（n=1） | 字符级内容保留率：乱序不改变字符多重集，因此对局部乱序免疫 | 0.25 |
| `bigram_coverage` | 同上（n=2） | 局部指纹：改一个字只破坏 2 个窗口 | 0.25 |
| `trigram_coverage` | 同上（n=3） | 对"连续照抄"极敏感，拉开"整段复制"与"改写重述"的差距 | 0.10 |
| `bigram_cosine` | 词频向量余弦 | 引入对称性与篇幅均衡，避免抄袭版更长时分数虚高 | 0.10 |

融合公式：

```
duplication = Σ_k w_k · s_k  /  Σ_k w_k
```

写成"除以权重之和"而不是直接加权求和，是因为顺序敏感信号在超长文本上
会被跳过（见 3.5），此时必须在剩余信号上**重新归一化**权重，否则分数会
凭空掉一截，"长文本天生低分"会变成系统性偏差。

#### 关键定义：为什么用 `Σmin / Σtf` 当主指标

查重的核心问题是"抄袭版里有多少内容来自原文"，把这句话直译成数学就是：

```
coverage = Σ_g min(tf_原文(g), tf_抄袭(g)) / Σ_g tf_抄袭(g)
```

分子数的是"能在原文中找到**足量**对应物的 n-gram 个数"。它有两条重要性质：

* 抄的是原文的**一小段**（摘抄式抄袭）→ 分子分母同比例缩小 → 仍接近 1.0；
* 把原文整篇复制两遍 → 原文对每段内容只"供得上"一次 → 分数减半，
  "复制粘贴凑字数"不能拉高重复率。

### 3.4 权重是怎么定的（不是拍脑袋）

权重由 `scripts/calibrate.py` 在**带标注的语料集**上实验选出，可复现。

语料集构造：课程下发的真实语料只有 `orig.txt` 与 `orig_add.txt`，删/乱序
变体并未公开，因此用 `scripts/make_variants.py` 按题面描述的三种手段合成
同等强度的变体，把每份的期望相似度标为语料命名中的 `0.8`，原文与自身比对
标为 `1.00` 作为上界。

在该语料集上比较候选权重方案的平均绝对误差（MAE）：

| 方案 | 字符级权重 | MAE | 最大误差 |
| --- | --- | --- | --- |
| A 只用文字 n-gram | 0.00 | 0.0999 | 0.2539 |
| B | 0.20 | 0.0704 | 0.1688 |
| **C 选定** | **0.25** | **0.0545** | **0.1318** |
| D 实验最优 | 0.30 | 0.0472 | 0.1070 |
| E 重二元组 | 0.10 | 0.0747 | 0.1868 |

**为什么没有直接采用实验最优的 D**：两者差距仅 0.0073，而语料集里 6/7 是
脚本合成的变体，这个差距落在样本噪声以内；D 把更多权重压到字符级信号上，
会削弱二元组指纹的贡献，对"整段照抄"这类最典型的抄袭反而更不敏感。
最终选定的 C 位于误差最优平台（0.04~0.06）的中央，取向更均衡。

### 3.5 超长文本的自适应降级

顺序敏感信号基于最长公共子序列，耗时随长度增长得比 n-gram 快，因此在
`MAX_SEQUENCE_CHARS = 50_000` 处设阈值。超过阈值时程序主动放弃这一路信号
并按比例分摊权重。该阈值能取到 5 万（原为 2 万）得益于第 3.6 节的重写。

这里有一条硬约束：`SequenceMatcher` 的最坏耗时是输入长度的乘积。实测
**3.4 万字符时 `difflib` 需要 8.46 秒**，已经足够让单次比对突破 5 秒时限，
所以这个阈值不是"优化项"而是"正确性项"。

### 3.6 位并行 LCS：一次 23 倍的提速

顺序信号原先用 `difflib.SequenceMatcher.ratio()`。性能分析显示，在真实语料
规模上它占了 **95.6%** 的运行时间（0.2633 s / 0.2750 s）——是真正的瓶颈。

替换为 Hyyrö (2004) 的位并行 LCS：把动态规划表的一整**行**编码成一个大
整数，用 `(V + U) | (V - U)` 一次推进整行。Python 的大整数运算是 C 实现的，
于是每 64 个 DP 单元只需一次机器字运算，等效复杂度降到
`O(len_a · len_b / 64)` 次机器字操作。

实测（真实语料上放大）：

| 输入规模 | `difflib` | 位并行 LCS | 提速 | 结果是否一致 |
| --- | --- | --- | --- | --- |
| 8,493 字符 | 0.2568 s | 0.0109 s | 23.7× | ✅ 一致 |
| 16,986 字符 | 1.0840 s | 0.0664 s | 16.3× | ✅ 一致 |
| 33,972 字符 | 9.3291 s | 0.2276 s | 41.0× | ✅ 一致 |

关键点：**在高相似文本上两者给出的匹配字符数逐位相同**（真实语料上
M = L = 8493，ratio = 0.905968），所以这是一次纯粹的等价替换，不是
"用精度换速度"。差异只出现在两篇毫无关系的文本上——那正是本信号取值
接近 0、对最终分数影响最小的时候。

另外，位并行实现的耗时**只与长度有关、与内容无关**，因此不存在"某些
恶意输入特别慢"的最坏情况。

## 四、接口设计

### 4.1 对外接口

```python
from plagcheck import PlagiarismChecker, write_answer_file

checker = PlagiarismChecker()
result = checker.compare_files("orig.txt", "orig_add.txt")
write_answer_file("ans.txt", result.duplication)
```

`plagcheck/__init__.py` 用显式 `__all__` 固定对外契约，内部模块可以自由重构。

### 4.2 关键接口一览

| 模块 | 函数 / 类 | 职责 |
| --- | --- | --- |
| `textio` | `read_text_file(path) -> str` | 读文件，自动识别 UTF-8/BOM/GBK/GB18030/UTF-16 |
| | `write_answer_file(path, duplication) -> str` | 写两位小数，返回实际写入的字符串 |
| | `format_answer(duplication) -> str` | 夹紧到 `[0,1]` 并格式化 |
| `normalize` | `normalize(text, *, keep_punctuation, casefold) -> str` | 归一化 |
| `tokenize` | `ngram_frequencies(text, n) -> dict` | n-gram 词频 |
| `similarity` | `coverage / cosine / jaccard(freq_a, freq_b) -> float` | 词频度量 |
| | `lcs_length / sequence_ratio(text_a, text_b) -> int / float` | 顺序度量 |
| `engine` | `PlagiarismChecker.compare_texts / compare_files` | 编排 + 融合 |
| | `SimilarityWeights` | 只读权重对象（负权重/全零权重在构造时即拒绝） |
| | `DuplicationResult` | 结构化结果（总分 + 各分项 + 耗时 + 字符数） |
| `cli` | `main(argv) -> int` | 参数解析、异常映射为退出码 |

### 4.3 几处刻意的设计取舍

* **`DuplicationResult` 返回结构化对象而不是裸浮点数。** 命令行只需要一个
  数字，但调试与博客举证需要"这个分数由哪几路信号、各占多少权重算出来"。
  多返回一点信息，几乎不增加成本，却让结果可解释。
* **标准输出默认保持安静。** 结果只写答案文件，诊断信息走标准错误且仅在
  `--verbose` 时输出。这样无论评测方如何捕获本程序的输出，都不会被污染。
* **答案文件不带结尾换行符。** 无论评测方是 `float(f.read())`、按行读取，
  还是与期望字符串严格比较，都能得到一致结果。
* **权重对象只读。** `SimilarityWeights` 是 frozen dataclass，构造时校验
  非负且总和为正，防止运行期被意外改写。
* **不写任何临时文件。** 这是"只能读写三个指定文件"的直接结果：不落缓存、
  不写日志、不做原子替换（那需要临时文件）。答案文件直接覆盖写入。

## 五、异常处理设计

每种异常都对应一类可独立诊断的故障，并绑定一个确定的进程退出码。
这样程序永远不会"抛异常崩溃退出"，而是"带诊断信息、以约定码退出"。

| 异常 | 退出码 | 触发场景 | 设计目标 |
| --- | --- | --- | --- |
| `ArgumentError` | 2 | 某个路径参数是空字符串 | 在碰磁盘之前拦住用法错误，给出正确示例 |
| `InputPathError` | 3 | 路径不存在 / 是目录 | 区分"路径有问题"与"内容读不出来" |
| `InputReadError` | 4 | IO 失败、超出大小上限、内存不足 | 把 `OSError`/`MemoryError` 统一翻译，杜绝崩溃 |
| `EmptyDocumentError` | 5 | 文件为 0 字节 | 显式报错，而不是让空文档算出"看似合法的 0.00" |
| `OutputWriteError` | 6 | 答案目录无法创建、写入失败 | 暴露"算完了结果却丢了"这种最危险的失败 |
| 其他未预期异常 | 1 | 兜底 | 打印诊断信息后受控退出，绝不抛 traceback |

与异常相邻但**不属于异常**的两种情形，按约定返回 `0.00`：

* 文件非空、但去掉标点空白后没有可比对内容（例如整篇都是标点）；
* 原文或抄袭版归一化后为空。

区别在于：0 字节文件是"输入非法"，而"整篇标点"是"合法输入但无法比对"。

此外，入口会尝试把标准输出的编码错误策略放宽为 `replace`。在英文版
Windows 上控制台编码可能是 cp437，直接 `print` 中文会抛
`UnicodeEncodeError`；而该异常发生在**错误处理路径内部**，会把"有诊断
信息的退出"退化成"崩溃退出"，正好踩中扣分项。

## 六、单元测试设计

212 个测试用例，行覆盖率 **100%**（322/322），见
[`coverage/coverage.txt`](coverage/coverage.txt)。

测试策略不是"比对魔法数字"，而是验证**必须成立的性质**：

| 层次 | 用例数 | 核心思路 |
| --- | --- | --- |
| `exceptions` | 9 | 异常是契约不是逻辑：逐条断言退出码唯一、消息原样保留 |
| `normalize` | 25 | 构造"应当等价"的文本对；再用等价性测试证明正则改写没有改变行为 |
| `tokenize` | 12 | 纯下标算术，把窗口边界逐个钉死（空串、恰好等长、短一个字符） |
| `similarity` | 62 | 小规模手算样本 + **与教科书 DP 实现随机化对拍** |
| `textio` | 40 | 按**故障模式**而非代码分支设计：编码不认识、传的是目录、文件为空… |
| `engine` | 44 | 端点性质 + **单调性**（破坏越多分越低）+ 不变性 + 退化输入 |
| `cli` | 20 | 黑盒 + 真实文件：真建文件、真调 `main()`、真读回答案 |

其中三条最有价值：

1. **随机化对拍**（`test_matches_dynamic_programming_reference`）：位并行 LCS
   与教科书 O(n·m) DP 在 250 组随机输入上逐一比对，证明它算的确实是
   最长公共子序列，而不是一个"看起来差不多"的量。
2. **等价性测试**（`TestRegexRewriteIsEquivalent`）：把性能优化前的逐字符
   实现保留为基准，证明正则改写逐字符等价。这条测试**真的失败过一次**，
   并暴露出一个我没预料到的差异——`str.lower()` 会应用 Unicode 的希腊
   词尾 sigma 规则（`ΣΟΦΟΣ` → `σοφος`），而逐字符 `lower()` 给出 `σοφοσ`。
   该差异对本项目无影响（两篇文档走同一条代码路径），但被如实钉在测试里。
3. **单调性测试**：`轻改 > 中改 > 重改`。这是唯一能跨语料验证、且直接对应
   "查重"这个词含义的强断言。

## 七、代码质量

| 工具 | 范围 | 结果 |

| `pylint` 2.16.2 | `plagcheck` + `main.py` + `tests` | **10.00 / 10，零告警** |
| `pylint` 2.16.2 | `scripts/`（3 个可分析脚本） | **10.00 / 10** |
| `flake8` 7.0.0 | 全部源码（含测试与脚本） | **0 条告警** |

配置文件：[`../pylintrc`](../pylintrc)，其中每一条 `disable` 都写明了理由
（例如 `__future__` 必须排在最前却被报 `ungrouped-imports` 属工具误报；
`__all__` 显式再导出必然与源模块重复文本，被 `duplicate-code` 误判）。

### 两个必须记录的工具链限制

1. **`scripts/profile_run.py` 与 `scripts/benchmark.py` 无法被 pylint 分析。**
   本机 pylint 2.16.2 依赖的 astroid 版本早于 Python 3.12，无法解析标准库
   `typing.py` 里的 PEP 695 类型别名语法，只要有任何模块 `import typing`
   就崩溃（`AttributeError: 'TreeRebuilder' object has no attribute
   'visit_typealias'`）。这两个脚本为了画图需要导入 matplotlib，而 matplotlib
   导入了 `typing`。它们由 flake8 覆盖（零告警）。
   同一个原因也让 `plagcheck/textio.py` 去掉了 `typing.Final` 装饰——那是
   一个可选的类型注解，去掉后整个包才能拿到干净的静态分析结果。
2. **覆盖率用标准库 `trace` 而非 `coverage.py`。** 评测环境无法联网安装
   （PyPI 镜像返回 403）。`trace` 能给出同样的"哪些行被执行过"信息，
   代价是慢得多、且不直接提供分支覆盖率。分支维度由针对每个判定分支
   显式编写的用例承担。

   顺带解决了 `trace` 的一个缺陷：`_Ignore._ignore` 按**文件基名**缓存
   （`_modname()` 对包返回 `"__init__"`），而 `ignoredirs` 里
   `site-packages/pytest/__init__.py` 会先把 `"__init__"` 标记为忽略，
   导致**所有** `__init__.py` 都不再被统计——这正是首版覆盖率报告里
   `plagcheck/__init__.py` 恒为 0.0% 的原因（`trace.py` 源码中亦留有
   `XXX _modname() doesn't work right for packages` 的注释）。

## 八、性能小结

真实语料（`orig.txt` 10,511 字符 vs `orig_add.txt` 12,274 字符）上的
单次比对：

| 指标 | 优化前 | 优化后 |
| --- | --- | --- |
| 端到端耗时 | 0.275 s | **0.022 s** |
| 顺序信号占比 | 95.6% | ~50%（绝对值从 0.263 s 降到 0.011 s） |
| 测试套件运行时间 | 1.16 s | 0.44 s |
| 启用顺序信号的长度上限 | 20,000 字符 | 50,000 字符 |

相对 5 秒时限有两个数量级的余量。详细的性能分析过程与图表见
[`profile/`](profile/) 与博客正文。

内存方面：程序对每个输入文件的字节数设了 512 MB 上限（超出即报错），
峰值内存主要由 6 个 n-gram 词频字典决定。真实语料下整篇文本的不同
2-gram 只有 5,563 个，内存占用在几 MB 量级，远低于 2048 MB 限制。
